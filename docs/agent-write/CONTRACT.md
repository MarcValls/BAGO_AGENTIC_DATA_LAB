## SDK contract (standalone first)
Extend existing src/workspace_sdk/workspace_service.py and its API dispatch, not a second coordinator. Persist proposals under the owned workspace internal directory with existing atomic/lock/path/text protections. New generic actions: prepare_write, review_write, revise_write, apply_write. Proposal IDs `write_<32 lowercase hex>`; revision opaque nonempty token; statuses PROPOSED, APPLIED, CONFLICT, UNCERTAIN (failures can be rejected without mutating proposal).

prepare_write arguments: path:string, text:string, mode:create|modify, context:{owner_kind:"agent",owner_id:string,conversation_id:string,conversation_revision:integer}. Model cannot supply context, expected hashes, confirmation or arbitrary workspace root. Core may accept caller context as provenance, not OS authentication. prepare is explicitly a proposal: NO target-file change. create requires absence; modify requires existing readable regular allowed UTF-8 file. Snapshot old bytes/hash for human review under lock; never return old content to model merely because proposal permission exists. Same SDK path/secret/size restrictions as write, and no symlinks/reparse escape; context files only where current SDK already explicitly permits writes. Keep before content and candidate hashes bound to proposal identity; persist full text, revision and digest. No adoption of foreign folders.

review_write arguments: proposal_id and context. Returns full review DTO {proposal_id, revision, workspace_id, path, mode, status, context, before_sha256:string|null, proposed_sha256:string, proposed_text:string, before_text:string, diff:string, review_sha256:string, receipt:object|null, observation:object|null}. review_sha256 binds proposal identity/revision, target workspace/path/mode/context, base hash and new content hash. Revalidate current base and report conflict/stale explicitly. No target effects; review/restoration is never confirmation.

revise_write arguments: proposal_id, expected_revision, text, context. Only PROPOSED, retains original target/base context, new revision and review hash; invalidates any prior approval. Reject stale revisions. Editing target means a new proposal, not silently changing approved scope.

apply_write arguments: proposal_id, expected_revision, review_sha256, context, confirmation:{confirmed:true,operation:"apply_write",workspace_id:string,proposal_id:string,revision:string,review_sha256:string}. Require exact equality with persisted proposal and review. Do NOT accept replacement path/text/root/hash in apply. Revalidate identity, paths, current base, content, review and proposal under the same workspace lock. Reuse _write and existing expected hash protections; avoid nested locks. Mark durable operation intent before effect, then record result/receipt with observed after hash. APPLIED replay returns existing receipt and never rewrites. If persistence/receipt fails after possible effect, return UNCERTAIN/observable error, retain intent and support read-only reconciliation on review/restart; no automatic retry or fabricated rollback. Restart with unresolved intent may observe target to report effect, but never silently execute. SDK local API/CLI remains usable without ADL or providers. Integrity is not authentication against an actor able to rewrite the entire store.
