INICIO

Leer una ejecución

Manual 01 · edición 1.3 · 15 octubre 2026

Guía para inspeccionar una ejecución del laboratorio, seguir su LocalTrace y revisar propuestas y recibos.

Abrir la aplicación

scripts\run-local-ui.ps1

Ejecuta el comando desde la raíz del repositorio. El launcher compila la interfaz, inicia la API local y abre la aplicación. Selecciona un puerto libre entre 8080 y 9000; usa la dirección que abre el propio launcher. Para dependencias, consulta docs/agent-chat-control/LOCAL_SETUP.md.

En la barra lateral, elige Inspect y después Decision Inspector. La interfaz es de solo lectura: no autoriza ni ejecuta acciones. Si no hay paquete de evidencias, indica que falta; no inventa una ejecución.

Alcance de la app. También incluye Chat, Capabilities, Agent Builder, Agent Runs y Agent Evaluation Lab. Conversar con un agente o ver una entrada no demuestra por sí solo que un trabajo se completara. Consulta portfolio/README.md para la demo gobernada.

01 · OBSERVAR

Decisión, claims y evidencia

Identifica el run antes de interpretar la respuesta.

Anota el run_id, la pregunta, la respuesta fuente y el estado de la ejecución.

Los contadores resumen referencias de evidencia, claims estructurados, eventos de traza y acciones propuestas. Una referencia recuperada dice que un documento o fragmento se consultó; no demuestra por sí sola una frase de la respuesta.

La interfaz no extrae claims del texto ni deduce relaciones claim-evidencia. En Conclusion, Claims, Evidence y Provenance, comprueba qué datos proporcionó la fuente. Si falta la revisión o snapshot, la frescura no queda establecida.

No confundas “evidencia consultada” con “evidencia que respalda una afirmación”. El vínculo debe venir explícitamente de la fuente.

Preguntas para revisar

  • ¿Qué ejecución estoy viendo?
  • ¿La fuente separó claims estructurados?
  • ¿Cada relación con evidencia aparece en los datos?
  • ¿Se informó la revisión y la frescura?

02 · SEGUIR

Leer LocalTrace

Orden y causalidad son datos distintos.

Abre Trace en el inspector. Revisa el trace_id, el run_id, la secuencia de eventos y las referencias registradas.

La secuencia indica orden. Solo un parent_event_id informado por la fuente expresa una relación padre-hijo; no infieras más causalidad.

IdentificadorQué identifica
run_idLa ejecución del agente.
LocalTrace trace_idEl registro local de eventos.
Jaeger Trace IDLa traza que consultó Jaeger local; puede ser distinto.

La interfaz no enlaza automáticamente el ID de Jaeger con el trace local. Si un dato falta, anótalo como no proporcionado.

03 · COMPROBAR

Acciones y recibos

Permiso, ejecución y resultado necesitan evidencias distintas.

  1. Propuesta: describe una intención.
  2. Autorización: indica si se permitió o denegó la solicitud.
  3. Ejecución: requiere que la fuente registre que el efecto ocurrió.
  4. Recibo: registra el resultado y debe asociarse a la misma ejecución.

Un permiso ALLOW no demuestra ejecución. Un SUCCESS sin recibo asociado no basta para verificar el resultado. El inspector asocia recibos solo si su run_id explícito coincide con el del agente. Un recibo sin identidad o de otro run queda sin verificar.

La coincidencia del run_id es una comprobación de identidad declarada por la fuente; no es una firma criptográfica.

04 · LOCALIZAR

Jaeger local (opcional)

Jaeger proyecta observabilidad; LocalTrace conserva la evidencia de eventos.

Se necesita Docker para reproducir la validación local documentada:

docker compose -p bago-otel -f infra/observability/docker-compose.yml up -d
python scripts/run_l15_otel_live_validation.py --check

Abre http://localhost:16686 y busca el Trace ID que imprima la ejecución actual. No reutilices el ID de una captura anterior. Al terminar, puedes detener Jaeger:

docker compose -p bago-otel -f infra/observability/docker-compose.yml down

Captura histórica de Jaeger. El grafo y los identificadores variarán al repetir el flujo.

La validación versionada del 8 de octubre observó 15 spans para aquella traza. Es evidencia histórica, no prueba del estado actual de Docker, AWS ni colectores remotos. Este recorrido no acredita envío remoto.

05 · PRACTICAR

Registra lo que observas

Escribe conclusiones que se sostienen en los datos.

  • run_id y estado de la ejecución.
  • Número de referencias y presencia de claims estructurados.
  • trace_id, eventos y relaciones padre informadas.
  • Propuestas, decisiones, efectos observados y recibos.
  • Si coinciden el run_id del recibo y el del agente.
  • Si consultaste Jaeger: Trace ID y spans observados.
Ejemplo de conclusión acotada: “El recibo declara el mismo run_id que esta ejecución y muestra resultado SUCCESS”. No afirmes que una referencia respalda una claim si el vínculo no está registrado.

Si algo no aparece

  • La app no abre: usa la URL que lanzó el script; el puerto puede variar. Revisa docs/agent-chat-control/LOCAL_SETUP.md.
  • No hay evidencias: la interfaz puede indicar que falta el paquete y ofrecer Agent Runs. La ausencia no demuestra que haya ocurrido una ejecución.
  • Faltan claims o soporte: la fuente no los proporcionó; no los infieras de una cita.
  • Jaeger no abre: verifica Docker y repite Compose. Si no se reproduce, deja el resultado como no verificado.

Glosario

Claim: afirmación estructurada de la fuente. Evidencia: referencia a documento o fragmento consultado. LocalTrace: registro local de eventos. Span: operación en la traza de Jaeger. Recibo: registro del resultado declarado por una operación.
